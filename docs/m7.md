# M7 Module Specification — Fact Verification Agent + Evidence Fusion Stub

## 1. Module Overview & Objectives

- **Module ID:** M7
- **Module Name:** Fact Verification Agent + Evidence Fusion Stub
- **Pipeline Stage:** Judgment Tier (Service S7) + Fusion Tier (Service S6 Stub)
- **Primary Objective:** Aggregate multi-source graph evidence for each atomic claim, compute evidence support/contradiction mass, perform 5-way fine-grained claim verification, cite source passage IDs, and generate corrected factual statements for refuted or partially accurate claims.

---

## 2. Key Architectural Decisions

1. **Evidence Fusion Engine (Service S6 Stub):**
   - Traverses all `CLAIM` nodes within the `EvidenceGraph` (or deserialized `GraphSnapshot`).
   - Extracts NLI entailment and contradiction scores from graph edges (`SUPPORTS`, `CONTRADICTS`, `RELATED_TO`).
   - Aggregates unweighted/recency-decayed support score and contradiction score per claim.
   - Assigns explicit `ConsensusType` (`SUPPORT`, `CONTRADICT`, `CONFLICT`, `NEUTRAL`, `INSUFFICIENT`).

2. **5-Way Verification Verdict Taxonomy:**
   - `SUPPORTED`: Evidence explicitly and unambiguously confirms the claim.
   - `CONTRADICTED`: Evidence directly refutes or contradicts the claim.
   - `PARTIALLY_SUPPORTED`: Evidence supports core elements of the claim, but key details are missing or inaccurate.
   - `INSUFFICIENT_EVIDENCE`: Evidence does not provide sufficient factual information to confirm or refute.
   - `CONFLICTING_EVIDENCE`: Reliable sources provide directly contradictory information.

3. **LLM Verification Agent with Fallback Security:**
   - **LLM Mode:** Prompts `FactVerifier` via OpenRouter (using `judge_primary` LLM role) with full context including claim, retrieved passages with dates, and fusion consensus summary.
   - **Post-Verification Checks:** Strictly enforces passage citations. If `CONTRADICTED` or `PARTIALLY_SUPPORTED` is assigned, requires `corrected_text`.
   - **Algorithmic Fallback:** If `use_llm=False`, LLM API fails, or evidence passages are empty, deterministically maps `fusion.consensus` to a 5-way verdict.

4. **FEVER Evaluation Label Mapping:**
   - `SUPPORTED` $\rightarrow$ `SUPPORTS`
   - `CONTRADICTED` $\rightarrow$ `REFUTES`
   - `PARTIALLY_SUPPORTED` / `INSUFFICIENT_EVIDENCE` / `CONFLICTING_EVIDENCE` $\rightarrow$ `NOT ENOUGH INFO (NEI)`

## 3. Data Interface & Schema Contracts

### Input Contract
- `query_id` (`str`): Unique query/sample identifier.
- `question` (`str`): Original user query or benchmark prompt.
- `claims` (`list[Claim]`): Extracted atomic claims (from M5).
- `graph` (`EvidenceGraph | GraphSnapshot | nx.MultiDiGraph`): Evidence graph from M6.
- `as_of_date` (`date | str | None`): Temporal anchor for verification (default: UTC today).
- `live_enabled` (`bool`): Flag enabling date-aware verification prompts and recency weighting.
- `use_llm` (`bool`): Flag toggling LLM verification vs fallback logic.

### Output Contract (`VerifyClaimsResponse`)
- `query_id` (`str`): Matches request ID.
- `results` (`list[ClaimVerificationResult]`): Per-claim verification details:
  - `claim_id` (`str`)
  - `claim_text` (`str`)
  - `verdict` (`ClaimVerdictType`)
  - `confidence` (`float`)
  - `explanation` (`str`)
  - `citations` (`list[str]`)
  - `corrected_text` (`str | None`)
  - `fusion` (`ClaimEvidenceFusion | None`)
- `overall_verdict` (`ClaimVerdictType`): Aggregated verdict over all claims.
- `supported_count` (`int`)
- `contradicted_count` (`int`)
- `insufficient_count` (`int`)
